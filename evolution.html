The road here · Jul 2025 → Jul 2026

From an autocomplete to a fleet.

One year ago the AI lived inside my editor and I drove every keystroke. Here's how it grew, step by step, into a crew of agents I orchestrate.

how the way I work · what what I built
  1. ~ August 2025
    how
    A rocky start with the AI tools
    Cursor Windsurf Copilot → web_ai_test · flopped
    Tried the AI coding tools everyone was talking about — Cursor, Windsurf, Copilot in Visual Studio. My test was a simple website with Google-auth login (web_ai_test); it never really worked, and honestly turned me off AI for a while.
  2. ~ August 2025
    how
    Claude Sonnet clicks — specs, not code
    me→ VS Code · Claude Sonnet → specifications
    Then I tried Claude Sonnet — and it clicked. The unlock wasn't having AI write the app; it was having it generate specifications for me. Far safer — nothing risky shipped — and it steadily built my confidence, skills, and trust. That habit grew straight into the provider prompts a month later.
  3. ~ September 2025
    howwhat
    Teaching Claude our domain
    Providers prompts → specs catalogs test scripts
    Began writing reusable prompts that teach Claude how our integrations work and why — starting with the Skanska docs (Sep 9) and, on Sep 10, “we will generate specs, and also analyze code.” Just as much, this taught me how to communicate with Claude. The specs, catalogs, and test scripts they generate are a running measure of progress. (Reorganized into Providers/_prompts that November.)
  4. November 2025
    what
    JD Edwards, 32-bit → 64-bit — finally
    jde-xmlrequest-csharp · Nov 15
    Migrated the JD Edwards integration from the 32-bit API to the 64-bit one — something I'd fought on and off for years and never gotten working. With Claude it finally came together. One of the moments that proved this was more than autocomplete.
  5. December 7, 2025
    howwhat
    Claude Code builds the AdminApp
    me→ Claude Code → dimension AdminApp
    The AI left the editor. One Claude Code in a Windows terminal built a whole application — the dimension AdminApp (first commit Dec 7, 2025). It's grown to 200+ commits and become one of the most valuable apps I have — my first taste of an agent that runs commands, not just writes lines. My main box was still Windows, but I had a Linux side machine and was already comparing the two.
  6. ~ January 2026
    how
    The move to Linux — and the Gas Town spark
    Windows → Linux tmux Tailscale beads
    The pivotal month. After weeks of running Windows and Linux side by side, the verdict was clear — I switched to Linux. Claude Code is native there: it understands decades of Unix tooling and wields it fluently, where on Windows it had constantly fought a system it didn't really understand. I also meshed the machines with Tailscale and read Steve Yegge's Welcome to Gas Town, which inspired both beads and the mayor — a dispatcher that hands out work. (Still two machines, one session each.)
  7. ~ February 2026
    how
    A parallel fleet
    me→ worker worker worker in tmux windows
    Multiple agents running at once in tmux windows — several workers going in parallel instead of one at a time. I was still the dispatcher.
  8. ~ February 2026
    how
    Untethered — Mosh + tmux
    phone → Mosh → tmux on my servers
    Installed Mosh on my phone to reach the servers and reattach to tmux — so I could check on and steer the work remotely, from anywhere, not just at my desk.
  9. ~ February 2026
    what
    A client app, entirely Claude-built
    Claude → lobar-projects · repo, Feb 7
    Built an entire app for a client — the lobar-projects repo (created Feb 7) — driven end-to-end by Claude, and let Claude fully control that repository: commits, pushes, all of it. A self-contained early experiment in autonomy, months before I trusted it on my main production work.
  10. February 19, 2026
    what
    Goodbye Hub — microservices go live
    the Hub · retired → auth jobs email relay + tests
    Broke apart the monolithic Dimension Hub and replaced it with a set of microservices (auth, jobs, email, message, relay, storage, webhooks) — and thanks to Claude each one shipped well tested. The retirement commit said it best: “Goodbye Dimension Hub! Thanks for all your help over the years.”
  11. ~ March 2026
    how
    Multiple mayors & a shared beads server
    mayor · m1 mayor · m2 → federated beads
    More than one mayor — really just two tmux sessions on two machines, each dispatching its own workers. And beads moved onto a federated (Dolt) server, so every machine shared one task list.
  12. ~ April → July 2026
    what
    onramp — prototype on the side, merged in
    onramp · Apr → refine w/ Sean & Nishant → public · last week
    Prototyped a new configuration for our integrations with Claude (the onramp repo, April), then refined it on the side over several weeks — showing it to Sean and Nishant and tweaking as we went — before folding it into the main codebase and making it public just last week. A good example of the everyday pattern: prototype on the side, prove it out, merge it in.
  13. ~ May 2026
    how
    Worktrees finally click
    worker → its own git worktree
    A talk at the April Ruby Meetup planted the idea of git worktrees; it clicked about a month later. Now every worker gets its own worktree + branch — real isolation, so parallel agents never step on each other.
  14. May 27, 2026
    how
    Onto a Team plan
    me → Claude Team · org account
    Moved from individual Claude accounts to a Team plan for the org — a shared workspace, admin controls, and room to run this at scale instead of one seat at a time.
  15. ~ June 2026
    whathow
    Procore approval app — built on holiday
    tiny laptop · on holiday → office server → Procore approvals
    Two days after Rob relayed that a client wanted a Procore approval workflow, I built it while on holiday — on a tiny laptop, with the work running back on my office server. Client request to working prototype in about 48 hours, nowhere near my desk. The remote setup (Mosh + Tailscale) made "away" irrelevant.
  16. ~ late June 2026
    how
    The rules get written down
    persistent memory workers: leave uncommitted mayor: commit · push · PR
    The setup stopped being ad-hoc. Claude began keeping persistent memory of my preferences and policies (~Jun 22), and the commit rules crystallized: workers leave changes uncommitted; the mayor commits, pushes, and opens PRs (largely because Claude writes better commit messages than I do); merge is never automated; every PR needs a human approval.
  17. ~ July 1, 2026
    how
    Magic words & a safety ladder
    stat · sweep sling · park ship it merge / deploy · human only
    Gave the whole thing a control model: one magic word per action (stat, sweep, sling, ship it), graded by how far each one reaches — and the most dangerous actions (merge, deploy, production) get no shortcut at all. Those stay a deliberate, human-only call.
  18. This week · July 2026
    how
    The advisor arrives
    advisor + me → mayor ×N
    A new role: a roaming advisor that reviews the mayors and owns the how (method, policies), while I own the what & why. The pieces finally became one model.
  19. May → July 2026
    what
    Bulley → Nexus1 — solo, live last weekend
    just me + Claude → live · last weekend
    Migrated the client Bulley onto CMiC's new Nexus1 UI — UAT-ready by May 8, live last weekend, done solo with Claude in about two months. The contrast is stark: the CMiC v10x→r12 migration was a big, multi-person effort — a whole team (Zoey, Davis, Nate, and others) over many months. Same platform, a fraction of the people and time.
  20. This week · July 2026
    how
    Driving Claude from my phone
    phone → Claude remote control
    Enabled remote control of Claude, so I can interact with it straight from my phone — reviewing, steering, even building this very timeline — without being at a machine. (In fact, right now.)
  21. Now
    how
    One human, an advisor, and fleets
    advisor me → mayor ×N → transient workers
    The current shape: I set the what & why, the advisor helps manage the how, mayors run transient workers, and merge / deploy / prod stay locked to me.
One year: editor → terminal → a coordinated fleet. The tool stopped being something I type into and became something I run.
